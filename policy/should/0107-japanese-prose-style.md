# 0107 日本語で応対するときは日本語で書く（不要なカタカナ語・英字語を避ける）

Level: SHOULD
Scope: ユーザーとの日本語でのやり取り、および日本語で書く文書・コメント。英語の設計文書・コード・識別子は対象外。

日本語で説明するとき、通常のソフトウェア工学で使わない英字語・カタカナ語を無理に散りばめると、可読性が下がる。

- 特に 動詞 は、明らかに広く使われているカタカナ語でない限り 日本語で書く。
  - 避ける: 「リコンサイルする」「アクティベートする」「バインドする」「サブスクライブする」
  - 用いる: 「調停する／収束させる」「活性化する／起動する」「束縛する／割り当てる」「購読する」
- 定着したカタカナ名詞（タスク、プロセス、メモリ、ファイル、デプロイ等）や、固有の構成要素名
  （supervisor, driver など）はそのまま使ってよい。
- 逆方向の過剰翻訳も避ける: 定着した技術語を無理に日本語へ訳すと、かえって不自然になる。
  - 避ける: 「押済み履歴」（実例 2026-07-30: push 済み履歴の過剰訳）
  - 用いる: 「push 済み履歴」「プッシュ済みの履歴」
  - 避ける: 「配備」（実例 2026-08-03: deploy の過剰訳。計画文書と応答の全体で使っていた）
  - 用いる: 「デプロイ」
  - 避ける: 「基線」（実例 2026-08-03: baseline の過剰訳。測定の設計を述べる文書で使っていた）
  - 用いる: 「ベースライン」
- 判断基準: 普通のソフトウェアエンジニアリングの日本語文章で自然に使われるか。迷ったら日本語を選ぶ。
- ソースコードの識別子・設定キー・状態値は原語のまま置く。訳してはならない対象であり、上の
  「動詞は日本語で」は適用しない。例: `spawn_subtask`、`assignee`、`state="queued"`、
  `work/_child_results/`、`RootDirectory`、`IPAddressAllow`、`RuntimeMaxSec`、`cargo vendor`。
  識別子は文章の語ではなく実在する記号への参照なので、訳した時点で grep できない別の語になり、
  読み手はコードと文章を突き合わせられなくなる。

Rationale: 目的は読みやすさ。専門用語の正確さと、不要な横文字の混入は別の問題として扱う。
Enforcement: 慣習とレビュー。日本語で書くたびの自己点検で守る（機械検査は無い。文体の当否は
文脈ごとに変わるため）。
