# OVERVIEW — uniqnode とは何か(やさしい解説・現在の姿)

<a id="cfa85cc2-0d72-49f2-b628-b9622589851b"></a>

自分の資料(ノート・仕様書 PDF・ウェブの保存)を全部入れておき、LLM が出典付きで引ける
記憶装置を目指すシステム。まず 1 台で動き、将来は自宅と実家のように複数台で知識を
持ち合う。この文書は、実装済みの土台をやさしい日本語で説明する。規範は SPEC.md、
未実装の層の解説は [docs/plan/OVERVIEW.md](#4e00f8f7-7cb7-4aff-8ed8-17d94ff56071) にある。

## 土台: 内容がそのまま住所になる

すべてのデータは「中身のハッシュ値 = 名前」で保存する。中身が 1 文字でも違えば別の
名前になる。この方式の帰結として、同じものを二度入れても増えず(自動の重複排除)、
名前さえ知っていれば中身の改竄を必ず検出でき、一度生まれたオブジェクトは二度と
変わらない。「上書きで直す」「消す」という操作は、この世界にはそもそも存在しない。

では世界はどう変わるのか。変化は二種類だけである。新しいオブジェクトを足すことと、
「いまどれが現行か」を指す名札(ref)を張り替えること。名札は各ノードが自分の署名付きで
書く可変なレコードで、時刻や「どれが現行か」のような運用情報はすべてこちら側に置く。
不変な「主張」と可変な「運用」を混ぜない、というのが設計全体を貫く分離である。

## 中身はグラフ

オブジェクトは 3 種類だけ: 生のバイト列(blob)、頂点(node)、辺(edge)。辺は「どういう
関係か」を表す型も頂点で持ち、2 個以上のメンバーを順序付きで束ねられる。オブジェクトの
中に現れるハッシュ参照は「これを運ぶときはあれも一緒に運ぶ」という宣言で、参照を辿った
一式(到達閉包)が複製や保存の単位になる。

## 分散と「開世界」

ノード同士は手動で登録した相手とだけつながり、署名付きレコードを定期的に交換する
(伝播交換)。ここに大事な約束がある: 「見つからない」は「存在しない」を意味しない。
沈黙は情報ゼロである。だから問い合わせの答えは「見つかった」「自分の知る範囲には無い」
「時間切れ」の三通りで、データ層は決して「この世に無い」とは言わない。

## 覚えておく責任

保存の約束は pin で表す: 「この根から辿れる一式を最低 N 台で持て」。各ノードは
「私は持っている」という保持表明を交換し合い、台数が足りなくなったら自分で取り寄せて
修復する。逆に複製要求ゼロのものは「世界が忘れてもよい」データである。

## 信頼は鍵で表す

ノードは鍵ペアで識別する。グループの公開鍵と k-of-n の証明書(たとえば家族の管理者
2 人が署名したノードは仲間、のような規則)で参加を管理し、鍵を 1 本外せば、その鍵が
関与した発行物はまとめて自動失効する。

## いまどこまで動くか

上記の土台(単一ノードの保存・複製・分散問い合わせ・レプリカ健全性・グループ鍵)は
すべて実装済みで、SPEC の適合レベル L0〜L4 に対応する。器としては完成しているが、
「文書」をまだ知らない。次に載る取り込み・検索の層は
