# 運用の覚え書き

## 電源断からの復帰

無停電電源が尽きて筐体が落ちた後は、封印していない書庫の末尾を検査し、途中で切れた
レコードを落としてから追記を再び始める。導出データは後から作り直せるので、復帰の手順
には入れない。

## 帯域の抑制

伝播交換に回す複製は、一度に流す量を上限で抑える。上限に達した要求は待ち行列に積み、
順に流す。回線を占有した側が優先されることは無い。

## 署名に使う算法

ed25519 で署名し、s256 で内容を指す。封筒の鍵は x25519 で交換し、本文は chacha20 で
包む。どれも実装を選ばない標準の組であり、版を上げるときは移行期間を設ける。

## 記録の保存期間

要求の記録は毎日ひとつの帳簿に落とし、七日ぶんだけ残して古い順に消す。帳簿は追記
だけで伸び、後から書き換えない。

## 保守の窓

計画停止は、同じ根の複製を持つ相手が二台以上あるときだけ行う。停止の前に保持表明を
配り直し、残った相手が根を保てることを確かめる。

## Clock skew

A wall clock that drifts by minutes changes nothing about verification, because the order of
records comes from the per-signer sequence number, and the clock is shown only in a listing.
