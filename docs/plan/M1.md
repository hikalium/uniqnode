# M1: 仕様の検証と最初の実装

<a id="07ccbcf7-722e-419f-8d7d-fb99e6cc3c20"></a>

現在の状態は [SPEC.md](../../SPEC.md) と、リポジトリ直下の旧プロトタイプ(TypeScript。移行完了後に
順次削除)。以下は次に行う作業を完了条件付きで列挙する。

## 1. シミュレータによる仕様 §8 の理論検証(仕様レビューと並行)

- sim/ クレート(Rust、標準ライブラリのみ)に離散イベントシミュレータを実装する。
  完了条件: `cargo test` で下記シナリオが決定論的に再現・検証できる。
  - DBノード脱落 → T_prop 後に DEGRADED → rendezvous 修復で SATISFIED に収束する。
  - 容量不足 → ALERT(capacity) が即時に、それ以外の長期不足 → ALERT(unknown) が T_heal 後に、
    それぞれ遷移として1回だけ発火する。
  - ネットワーク分断と合流 → 過剰レプリカが降格規則(§8.3)で収束し、収束過程で観測可能な
    保持数が min_replicas を割らない(割る事例が見つかれば仕様の欠陥として記録する)。
  - min_replicas=0 のオブジェクトが evict 圧力下で全所から消滅し得る(エラーではない)。
  - evict が確約層に触れない。参照カウント保護が機能する。
  - 修復の同時実行数が不足数を大きく超えない(雪崩の不在)。
- 発見事項を docs/analysis/ に日付付きで記録し、SPEC.md の §8 の既定値・規則に反映する。
  完了条件: 分析文書がコミットされ、仕様との差分がゼロ(仕様側を直したか、欠陥なしと記録したか)。

## 2. L0 実装(単一DBノードのストア)

- 正規化 JSON(c1)・SHA-256・オブジェクトストア(pack + MANIFEST + ref ログ + fsck)を
  Rust(標準ライブラリのみ)で実装する。
  完了条件: SPEC §11 の L0 を満たし、取り込み中の kill -9 から再起動で回復し fsck が全件通る。
- ノードローカル API(SPEC §10 のローカル部分)。
  完了条件: curl で objects/refs/query(ローカル)が往復し、旧プロトタイプの
  「ノードと関係の出し入れ」機能を代替できる。

## 3. 旧コードの削除

- L0 の API が旧プロトタイプの機能を代替した時点で、対応する旧ファイル(src/, views/, static/,
  package.json ほか)を削除する。
  完了条件: リポジトリに TypeScript / npm 由来のファイルが残っていない。

## 4. ポリシー機械化

- lamalium の check-docs / check-policy に相当する検査(強調記法・ポリシー形式・アンカー参照)を
  uniqnode のテストとして実装する。
  完了条件: `cargo test` が policy/ と docs/ の形式違反で赤になる。
