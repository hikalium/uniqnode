## 発見: 「0%」は計測チャネルの盲点だった(should/0128 の実例)

最初の計測では api.rs / http.rs が 0% と出た。テストが無いのではなく、統合テストが serve
子プロセスを SIGKILL で止めるため、LLVM のプロファイルが書き出されない(書き出しはプロセスの
正常終了時)という計測チャネルの盲点だった。「0% = 検証されていない」と主張する前に、
チャネルがそれを観測できるかを確認すべき事例がまた1つ増えた。

対処は計測のためだけでなく運用面でも正当なもの:

1. `POST /v1/admin/shutdown`(応答後に正常終了)を追加した。SPEC §10 に記載。
2. その過程で実物の競合を1つ踏んだ: 停止要求側がリクエスト書き込み直後にソケットを閉じると、
   サーバ側の応答書き込みが EPIPE で失敗して `?` で抜け、終了処理に到達しないことがある
   (curl は応答を待つので再現しない)。サーバは応答書き込みの成否に関わらず終了するよう、
   クライアントは応答を読み切ってから閉じるよう、両側を直した。
3. クラッシュ試験(node/tests/crash.rs)は意図的に SIGKILL のまま(それが試験の本体)。
