# VIEWER — RAG ビューワ(1 枚の HTML・serve への転送・uniqnode viewer)

<a id="4cd4c71a-ecf3-44a8-a97b-bb2c8d8fe847"></a>

読み手は、ビューワのコード(node/src/viewer.rs、node/src/viewer.html、node/src/main.rs の
viewer サブコマンド)を読む者と、ブラウザから取り込み済みの文書を引きたい者。検索そのものの
実装は [docs/design/SEARCH.md](#19574e78-9bf5-4f87-a4c2-c4a10222c580)、同じ検索を LLM
エージェントへ出すアダプタは [docs/design/MCP.md](#dacd474d-424a-45d5-a278-766fc2465dd9) に
ある。この文書はビューワの現在の実装を記述する。

この層は薄い被せ物である。方式の既定・劣化の判断・引用の組み立ては node/src/api.rs の
run_search が持ち、ビューワがするのは 1 枚の HTML を出すことと、その頁が呼ぶ口を走っている
serve へ転送することだけである(検索の判断を二重に実装しない。should/0135)。MCP アダプタの
転送する形と同じ立ち位置で、相手が LLM かブラウザかだけが違う。

## 起こし方

```
uniqnode viewer <data_dir> <host:port> [--serve-url <url>] [ログの指定]
```

- 転送先の既定は定数 DEFAULT_SERVE_URL(http://127.0.0.1:7440)。`--serve-url` で替える。
- 自分でストアを開かないので排他錠を取らない。serve が常駐したまま起こせるし、ビューワを
  起こしたまま ingest と embed も回せる(MCP の転送する形と同じ性質)。
- データディレクトリは開くためではなく、届かないときに「どの serve を起こせばよいか」を
  言うためと、ログの置き場を決めるために要る。ログは既定で `<data_dir>/logs/viewer.log`
  ([docs/design/LOGGING.md](#14a4e260-70af-4c52-9f19-1c116bddd004))。
- 束縛先は標準出力に 1 行 `listening on <addr>` で出す(serve と同じ取り決め。`:0` で
  自動割当にしたときに、起こした側が実際のポートを読める)。
- 誤った `--serve-url`(根を指さない・https)は起動時に断る。ブラウザを開いてから 500 を
  見るより、起動時に落ちる方が早く直せる。

## 転送する口は 5 つだけ

| 頁がすること | 口 |
|---|---|
| 素性の表示(node id・オブジェクト数) | `GET /v1/status` |
| コレクションの選択肢 | `GET /v1/refs` |
| 検索 | `POST /v1/search` |
| 「全文」ボタン | `GET /v1/objects/{id}` |
| 出典の照合 | `GET /v1/objects/{id}/citation` |

- これ以外はすべて 404 で、断り方に「何なら通るのか」を書く(must/0022)。
  「`/v1/` で始まれば何でも通す」にすると、ビューワの口がストア API 全体への素通しに
  なる。書き込みの口(`POST /v1/objects`・`PUT /v1/collections/…`)も、`POST /v1/sync` も、
  `POST /v1/admin/shutdown` も、ビューワからは届かない。
- `{id}` は c1 のオブジェクト ID の形(`s256:` と 16 進 64 桁)を確かめてから通す。転送先へ
  組み立てるパスに、要求の文字列をそのまま入れないためである(must/0020)。
- 相手の応答は中身を読まずにそのまま返す。誤りの本文も含めて serve が言ったことがブラウザに
  届く。種別は octet-stream で通す: `GET /v1/objects/{id}` はチャンクの c1 JSON も PDF の
  原文 blob も同じ口から返すので、こちらで JSON だと名乗ると嘘になることがある。
- 転送先が死んでいても頁は出る。届かないことは 502 の本文で言い、原因と `uniqnode serve` の
  起こし方を添える(黙って空を返さない)。

## 頁

- 資材は node/src/viewer.html に置き、`include_str!` で実行ファイルに束縛する
  (should/0112: 別言語の大きな文字列は自分のファイルに置く。コンパイル時に束縛するので、
  資材の欠落は 404 ではなくコンパイルエラーになる)。
- 外部資源を一切参照しない(CDN・フォント・画像・解析用の何か、いずれも無い)。繋がって
  いない機械でも開ける。問い合わせ先は同じ生成元の `/v1/*` だけなので、CORS も要らない。
- 操作できるのは検索要求の項そのものである: 問い・コレクション・方式(既定 / bm25 /
  embedding / hybrid)・件数・低情報チャンクを出すか。
- serve が言った注記はそのまま画面に出す。使った方式と得点の意味、劣化の理由(`degraded`)、
  低情報として落とした件数と戻し方である。黙って劣化しない・黙って捨てないという性質は、
  応答の欄をそのまま描くことで画面にも通す(should/0128、must/0019)。
- 一致が無いときは「一致なし。ここに無いことは、世界に無いことを意味しない」と書く
  (開世界。SPEC §7.2)。
- 各件は「コレクション/文書名 p.ページ」「位置・取得日時・得点」「見出し」「抜粋」
  「チャンク ID」と、全文を開くボタンである。全文はチャンクのオブジェクトを取って本文だけを
  出し、チャンクでない・c1 でないものは生のまま出す。
- PDF 由来でない件には「原本(文書全体)を開く」が付く。道は検索の応答が言った source_url
  ([docs/design/SEARCH.md](#1109a04b-923e-4493-8f00-d704047d6a2a) の POST /v1/search)を
  そのまま使い、頁は形(`/v1/objects/` で始まる同じ生成元の道)だけを検めて href に置く。
  応答から来た字面をそのまま href にすると `javascript:` の類が頁の上で走るためである。
  目録を引かないので件数の上限も要らない。
- PDF 由来の件には写しの箱(サムネ・拡大・原本の当該ページ・そのページだけの PDF)が付く。
  こちらは写しの目録が要るので、上位 3 件だけ引いて、残りには同じ形を当てる(写しが出せるか
  どうかは機械の性質で決まり、件ごとに変わらないため)。
- 全文を取る道には、チャンク ID をそのまま置く。この API のパスは生のまま扱う規約
  (パーセントデコードしない。node/src/http.rs)なので、`s256:` のコロンを %3A に直すと、
  受け側の ID の形の検査に落ちて 404 になる。
- 入力欄と選択肢は、背景と文字をいつも色の組で指定する(Canvas / CanvasText。:root の
  color-scheme に追従するシステム色)。片方だけを指定すると、開いた選択肢が地の色を失う:
  選択肢は別の描画面に出て頁の色を継がないので、暗い配色で白地に白文字になる。
- 取得日時は unix 秒を UTC で描く(MCP アダプタと同じ描き方。引用の at は、その版をこの
  DBノードの見えに置いた ref レコードの時刻である)。
- ストアから来る値(本文・文書名・コレクション名・チャンク ID・見出し)は、必ず escapeText を
  通してから頁に入る。取り込んだ文書の本文が `<script>` を含むことはありうるので、素通しに
  すると取り込んだ文書が頁の上で走る。値が入るのは本文の位置だけで属性値には入らないため、
  変換するのは `&` `<` `>` の 3 文字である。この規律は単体試験
  every_value_from_the_store_is_escaped_before_it_reaches_the_page が資材に対して機械的に
  確かめる。

## 意図的に持たないもの

- 書き込みの口。ビューワは読むだけである。取り込みは CLI か serve の REST で行う。
- 認証。serve と同じ信頼境界に置く(既定の待ち受けは loopback で、ネットワークへ出すなら
  serve と同じく暗号化・認証済みチャネルの上に置く。SPEC §6.2)。
- ストアを直接開く形。MCP アダプタは持っているが、ビューワは転送する形だけである。
  ブラウザから引きたい場面では serve が走っている。
- 分散検索(`peers`)の指定。今は自分のDBノードの索引だけを引く
  ([docs/design/DISTRIBUTED_SEARCH.md](#e577f6db-659e-4eb8-a152-3b7780e4a9d1))。
- 構築ツール。頁は 1 枚の HTML で、依存も最小化の工程も無い。

## 既知の癖

- 初回の検索は serve 側の索引構築を待つ(実データ規模で約 9 秒。
  [docs/design/SEARCH.md](#19574e78-9bf5-4f87-a4c2-c4a10222c580) の「既知の癖」)。1 本の転送の
  期限は 60 秒で、MCP の転送する形と同じ長さである。
- PDF から取り込んだチャンクは見出しを持たないので、見出しの行は出ない(代わりにページ番号が
  出る。INGEST (uuid:47d69a3e-c39a-4e76-9814-e9c24240293b) の「既知の癖」)。
- コレクションの選択肢は `GET /v1/refs` の全件から組む。ref が増えるほどこの応答は大きく
  なるが、頁を開いたときの 1 回だけである。
